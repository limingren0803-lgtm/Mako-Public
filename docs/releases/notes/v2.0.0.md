# Mako v2.0.0 发布说明

发布日期：2026-08-14

## 求职工作台

v2.0.0 将六项 Career Skill 整合到统一的 Web 工作台中，覆盖背景诊断、方向匹配、JD 分析、简历优化、面试准备和行动规划。各板块采用选择功能、提供材料、确认输入和查看结果四步流程，支持直接输入文本以及读取 UTF-8 编码的 `.txt`、`.md` 文件。

工作台入口为 `/mako/`，`/app/` 作为兼容入口保留。页面与 FastAPI 使用同源静态资源，不增加独立的前端构建链。

## 请求级岗位匹配

方向匹配板块可以搜索本地已审核且仍在用户所选时效窗口内的职位。具备结构化 JD 数据的岗位会展示经过审核的职责或任职要求，由用户选择本次需要核对的原文条目和关键词。

服务端会确认关键词实际存在于对应 JD 原文，再将用户确认的经历与要求逐项比较。结果区分为已覆盖、部分覆盖、存在差距、待补充和不适用，并保留理由与待确认问题，不生成缺少解释依据的综合分数。

用户材料和匹配结论只在当前请求中处理，不写入 CareerProfile、Redis、ChromaDB 或长期证据库。工作台不读取管理密钥，也不调用受保护的管理接口。

## 数据与审核边界

V2 增加了证据、用户确认、JD 要求提取、人工审核和岗位匹配的数据契约。相关管理接口继续使用 `X-Admin-Key` 保护；未经审核的职位版本或 JD 要求不能进入正式匹配。

职位来源仍采用企业官网或由企业官网明确链接的招聘入口。聊天和工作台请求不会实时抓取外部网站，官网不可用时也不会绕过登录、验证码、robots 规则或访问限制。

## 兼容性

- 六项 Career Skill、CareerProfile、Redis Working Memory 和 ChromaDB Episodic Memory 行为保持兼容；
- `/chat`、`/monitor` 等既有 API 路径保持不变；
- Redis key、ChromaDB collection 和现有 Docker volume 名称保持不变；
- V2 证据登记使用独立 SQLite 路径，不迁移或覆盖现有持久化数据。

## 公开验证

- 公开回归测试：133/133 通过；
- Python 版本元数据、V2 数据契约与逐项匹配：通过；
- 请求级工作台流程、JD 原文约束与零长期写入：通过；
- 管理接口权限、输入边界和 UI 凭据隔离：通过；
- Docker Compose 配置与凭据模式扫描由仓库 CI 持续检查。

## 当前边界

PDF、DOCX、终端用户账户、跨设备恢复和长期个人证据管理尚未开放。工作台只对具备已审核结构化 JD 条目的岗位提供逐项匹配；其他有效岗位仍可通过常规方向匹配使用。

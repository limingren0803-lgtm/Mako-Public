# Mako v2.10.0 发布说明

## 从简短诊断开始

首次使用可以先提供简历，选填当前困扰、投递情况和岗位信息，没有 JD 也能开始初步诊断。结果集中呈现优先问题、依据与下一步，并保留不确定性的说明。

用户可以收起弹窗后在当前页面继续，按需选择刷新后的保留方式，也可以把诊断保存为求职任务。保存简历默认不勾选；选择保留后，规范化简历文本存入个人材料库并由任务引用，不长期保存原始 Word/PDF 文件。保存后可进入推荐工具的准备页，不自动发起下一次分析。

## 简历修改稿更便于使用

简历优化将修改稿集中展示，并提供复制按钮；修改说明与待确认信息分开展示。支持整份改写和按用户要求修改单段，旧格式或不完整结果保留原文回退。

连续任务改用临时简历或明确不使用简历时，本次分析不会沿用旧简历的初步判断和任务对话。库内任务简历的连续分析保持原有行为。工具弹窗的阅读进度条限定在内容区域，并修正隐藏文件控件造成的横向溢出。

## 反馈问题修复

- #5：解析器与材料模型共用分段上限，超限提前停止；预览、保存和临时分析返回明确的 413 错误，不再因分段超限返回 500。不会静默合并或截断段落。
- #6：重复导入已拒绝版本保持原审核决定，不制造错误待审引用，不覆盖其他待审版本；重复导入历史批准版本不会覆盖当前职位信息。
- #9：同一指标和标签的持续异常合并为一个告警，恢复后解除，再次异常创建新事件。最多保留最近 1000 条，超过上限淘汰最旧项，包括尚未恢复的旧项。
- #11：删除不可达的自动多 Agent 并行分支，修正能力说明。常规求职请求仍按意图路由，显式并行接口保留，不表示六阶段自动串行执行。
- #7：启动配置与文档明确单 API 进程、单应用实例限制，并提示可识别的不支持配置；没有新增跨进程的请求或会话协调。
- #3：补充[六阶段求职示例](../../guides/career-workspace-example.md)，使用虚构材料展示输入、确认点、输出、修正和保存方式。

## 升级与使用边界

既有 API 继续兼容；新增诊断保存入口，不改变现有数据库 schema、Redis key、ChromaDB collection 或持久化挂载目标。更新不会自动改写已经保存的分析。

职位修复针对后续导入操作，不包含旧错误待审引用的批量清理，也不新增已拒绝版本的重新送审功能。如旧环境已有异常记录，应先备份并核对后再处理。

模型仍可能补写材料未提供的动作或成效。本版不能保证消除此类事实扩写，复制使用前仍需逐句核对；流程测试通过不等于所有模型输出都正确。

请求缓存和工作区会话仍位于进程内，不支持多 worker 或多应用副本。具体窗口、失败重试和重启边界见[部署与请求重试说明](../../guides/deployment-boundaries.md)。本版不提供云端账号、跨设备同步或多人平台。
